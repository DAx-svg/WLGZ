  二、开机自启修复
================================================================================

问题：每次重启电脑后 http://127.0.0.1:8080 打不开
根因：Flask 服务未设置开机自启，进程随关机终止

解决：
  - 创建计划任务 WlgzApp：开机延迟30秒启动 app.py
  - 首次配置失败原因：schtasks 用 SYSTEM 账户运行，PATH 中无 python
  - 修复：使用完整 Python 路径 C:\Users\1\AppData\Local\Python\bin\python.exe

命令：
  schtasks /Create /SC ONSTART /TN "WlgzApp" /TR "C:\Users\1\AppData\Local\Python\bin\python.exe D:\板卡物料追溯系统\app.py" /DELAY 0000:30 /F

================================================================================
  六、updated_at 时间戳仲裁（v2.6 核心更新）
================================================================================

问题背景：
  用户平时在云端加 SN，云端崩了时在本地应急操作
  旧逻辑：冲突时"云端盲赢"→ 云端恢复后旧数据覆盖本地新操作
  用户需求：谁最后改谁赢

实现方案：

  数据库层（app.py init_db）：
    1. materials 表新增 updated_at TEXT DEFAULT '' 列
    2. 兼容迁移：ALTER TABLE ADD COLUMN + try/except
    3. 触发器 tr_materials_ins：INSERT 时自动设置 updated_at
    4. 触发器 tr_materials_upd：UPDATE 时自动刷新 updated_at

  同步层（sync_db.py 第8节重写）：
    原逻辑：状态冲突 → 以云端为准
    新逻辑：比较 local.updated_at vs cloud.updated_at
      - 本地 > 云端 → 推本地到云端
      - 云端 > 本地 → 保留云端
      - 本地有时间戳、云端空 → 本地赢
      - 云端有时间戳、本地空 → 云端赢
      - 都没有时间戳 → 云端赢（兼容旧数据）

  优势：
    - 无需修改任何 INSERT/UPDATE 语句（触发器自动处理）
    - 未来新增代码自动享有时间戳保护
    - 向后兼容（旧数据无时间戳时云端为准）
