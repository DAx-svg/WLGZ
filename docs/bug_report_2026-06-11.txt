🔴 Bug 1（严重）：CSV 导出全部 500 错误
----------------------------------------------------------------
位置：app.py 第 1507-1517 行  _make_csv_response() 函数

现象：
  点击首页"导出"下拉菜单中的任意选项（物料清单/出库记录/售后工单/
  故障记录/操作日志），均返回 HTTP 500 "Internal Server Error"。

根因：
  sqlite3.Row 对象没有 .get() 方法。第 1514 行：

    writer.writerow([row.get(c, '') for c in columns])

  这里的 row 是 sqlite3.Row 类型，只支持 row['key'] 下标访问，
  不支持 row.get('key', default) 字典方法。

影响范围（5 个端点全部崩溃）：
  - /api/export/materials      — 物料清单 CSV
  - /api/export/outbounds      — 出库记录 CSV
  - /api/export/aftersales     — 售后工单 CSV
  - /api/export/faults         — 故障记录 CSV
  - /api/export/operation_logs — 操作日志 CSV

验证过程：
  1. curl 测试所有 5 个端点 → 全部返回 500
  2. 错误页面显示：AttributeError: 'sqlite3.Row' object has no attribute 'get'
  3. 直接执行 SQL 验证数据存在（22 条物料），排除空表问题


🔴 Bug 2（严重）：操作日志完全不记录
----------------------------------------------------------------
位置：app.py 第 291-302 行  log_operation() 函数

现象：
  - operation_logs 表始终为空（0 条记录）
  - 创建品类、出库、盘点等任何操作后查询日志 API 均返回空
  - /logs 页面显示"暂无操作日志"

根因：
  两重问题叠加导致：

  问题 A：log_operation 函数缺少 db.commit()
    def log_operation(op_type, sn='', detail=''):
        try:
            db = get_db()
            db.execute("INSERT INTO operation_logs ...", (...))
            # ← 这里缺少 db.commit()！事务未提交
        except Exception:
            pass

  问题 B：调用时序错误
    所有路由处理函数的模式如下：
      db = get_db()
      db.execute("INSERT/UPDATE/DELETE ...")  # 业务操作
      db.commit()                             # 提交业务操作
      log_operation(...)                      # ← 在 commit 之后调用！

    log_operation 中的 INSERT 开启了一个新的隐式事务，
    但这个事务永远不会被提交。当请求结束、数据库连接关闭时，
    未提交的事务被 SQLite 自动回滚。日志记录就此丢失。

验证过程：
  1. 通过 API 创建品类 → 检查 operation_logs 表 → 0 条记录
  2. 通过 API 执行库存盘点 → 检查 operation_logs 表 → 0 条记录
  3. 直接 Python 操作数据库：db.execute(INSERT) + db.commit() → 写入成功
  4. 直接 Python 操作数据库：db.execute(INSERT) 不 commit → 关闭连接后记录消失
  → 确认是缺少 db.commit() 导致

修复 1：CSV 导出（Bug 1）
----------------------------------------------------------------
文件：app.py
位置：第 1507-1517 行

方案 A（推荐，改动最小）：
  在 _make_csv_response 函数中，先检查 row 类型：

    def _make_csv_response(rows, filename, columns):
        output = io.StringIO()
        output.write('﻿')  # UTF-8 BOM
        writer = csv.writer(output)
        writer.writerow(columns)
        for row in rows:
            # 兼容 sqlite3.Row（无 .get 方法）
            if isinstance(row, dict):
                writer.writerow([row.get(c, '') for c in columns])
            else:
                writer.writerow([row[c] if c in row.keys() else '' for c in columns])
        resp = app.response_class(output.getvalue(), mimetype='text/csv; charset=utf-8')
        resp.headers['Content-Disposition'] = f'attachment; filename="{filename}"'
        return resp

方案 B（更干净）：
  在所有调用处将 rows 转为 dict 列表再传入：

    rows = db.execute("SELECT ...").fetchall()
    rows = [dict(r) for r in rows]  # 加这一行
    return _make_csv_response(rows, '物料清单.csv', cols)

  推荐方案 B，因为不影响 _make_csv_response 的简洁性。


修复 2：操作日志不记录（Bug 2）
----------------------------------------------------------------
文件：app.py
位置：第 291-302 行

方案：
  在 log_operation 函数中添加 db.commit()：

    def log_operation(op_type, sn='', detail=''):
        """记录操作日志（审计追溯）"""
        try:
            db = get_db()
            now = datetime.now(ZoneInfo('Asia/Shanghai')).strftime('%Y-%m-%d %H:%M:%S')
            db.execute(
                "INSERT INTO operation_logs (op_time, op_type, sn, detail, operator_ip) "
                "VALUES (?,?,?,?,?)",
                (now, op_type, sn, detail, request.remote_addr or ''))
            db.commit()  # ← 添加此行
        except Exception:
            pass  # 日志记录失败不能阻塞主操作

注意：
  - 需要先创建与业务操作不同的数据库连接，或确认业务操作的 commit
    与日志 commit 不会互相干扰
  - 实际上 get_db() 返回的是同一个连接（g.db），所以 commit 会同时
    提交之前的任何未提交操作。但由于各路由在调用 log_operation 之前
    已经调用了 db.commit()，所以不会有未提交的业务数据。


修复 3：物料时间线 500 错误（Bug 3）
----------------------------------------------------------------
文件：app.py
位置：第 1732-1820 行

方案：
  将所有 r.get('xxx', default) 替换为兼容写法：

  第 1758 行：
    旧：r.get('courier_company','')
    新：r['courier_company'] if 'courier_company' in r.keys() else ''

    旧：r.get('tracking_number','')
    新：r['tracking_number'] if 'tracking_number' in r.keys() else ''

  第 1771 行：
    旧：r.get('completed_time')
    新：r['completed_time'] if 'completed_time' in r.keys() else None

  第 1776 行：
    旧：r.get('remarks', '')
    新：r['remarks'] if 'remarks' in r.keys() else ''

  第 1789 行：
    旧：r.get('resolved_time')
    新：r['resolved_time'] if 'resolved_time' in r.keys() else None

  第 1794 行：
    旧：r.get('solution', '')
    新：r['solution'] if 'solution' in r.keys() else ''

  更简洁的方案（推荐）：
  由于 outbound_records 表是通过 CREATE TABLE IF NOT EXISTS 和
  后续 ALTER TABLE ADD COLUMN 逐步演进的，列一定存在（至少有空默认值）。
  因此可以直接用 r['column_name'] 下标访问，不需要 hasattr 判断。
  但 .get() 的使用原意是防御性编程（万一列不存在）。建议保留防御性，
  统一使用 r['xxx'] or ''（空字符串在业务上等价于无值）。
